# W10 预习 · Function Calling / MCP / 普通 API 调用（各一句话）

| 概念 | 一句话 |
|---|---|
| **Function Calling** | **模型侧**的机制：模型不执行任何代码，只输出「我要调哪个函数、参数是什么」，由我们的程序去执行再回喂。 |
| **MCP**（Model Context Protocol） | **工具侧**的协议：把「工具怎么描述、怎么被发现、怎么被调用」标准化，让模型能接上别人写的、跑在别处的工具。 |
| **普通 API 调用** | 我们自己在代码里写死「什么时候调哪个接口、传什么参」，模型只负责生成文本，不参与决策。 |

**三者关系**：普通 API 是「人决定调什么」；Function Calling 是「模型决定调什么，但工具在本机、由我的代码执行」；MCP 是「模型决定调什么，工具在别处，用统一协议连过来」。W9 我们手写的 60 行循环 = Function Calling 的最小实现；W10 要换成 MCP 这套标准接口。

## 我希望 MCP 帮我接上的 2 个外部工具

### 1. 生词表服务 `vocab_service`

- **现状**：生词表现在是我仓库里的 `data/生词表.csv`，只有 15 个词，加了新课文就得手改 CSV。
- **希望 MCP 接上什么**：一个统一的词表服务（可以是学校词库、也可以是某个开放词表 API），能按词查等级、释义、例句，还能按等级列词。
- **输入**：`{"word": "把"}` 或 `{"level": 3, "limit": 50}`
- **输出**：`{"word": "把", "level": 3, "pinyin": "bǎ", "meaning": "介词，表示处置", "example": "我把书放在桌子上"}`；查不到返回 `{"found": false}`
- **为什么适合 MCP**：词表是共享资源，多个助手（我的、同学的、以后做的）都该用同一份，不该各自复制 CSV。

### 2. 成绩与作业本服务 `gradebook`

- **现状**：算分工具 `calc` 只能算「35*24」，算不了「这次听写全班平均分」——数据在我自己的 Excel 里。
- **希望 MCP 接上什么**：一个只读的成绩服务，能查某次测验的学生分数、算平均分与及格率；写入走另一条有权限的通道。
- **输入**：`{"quiz_id": "听写03", "action": "stats"}`
- **输出**：`{"count": 32, "average": 82.5, "pass_rate": 0.91, "missing": ["f25210103"]}`
- **为什么适合 MCP**：涉及学生隐私，必须由服务端控制权限与脱敏，不能让每个助手自己去读 Excel；这也呼应「隐私数据不出本机/不出服务」的红线。

## 一句话总结

**Function Calling 解决了「模型会说」，MCP 解决「工具从哪来、怎么接」**——前者是模型的能力，后者是生态的接口。W9 我把工具写在自己电脑上，W10 要学会把工具当成外部服务来接。
