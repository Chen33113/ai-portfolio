# 作业 2 附：README 的「已知问题」为什么要诚实写（约 200 字）

写「已知问题」不是为了自曝其短，是为了让**下一个用的人少踩一次坑**。

这份 README 里我写了两条：本地 0.5B 中文质量有限、没配云端 key 时只能跑本地。这两条如果不写，同学照着装、照着跑，看到「12 条把字句」这种离谱答案，第一反应会是「代码坏了」或者「作者在糊弄」，然后花半小时排查一个根本不存在的 bug。

主动写清楚，等于提前告诉对方：**这是已知的边界，不是故障**——想更好就换 `prefer="api"` 或换更大的模型。

还有一层：写已知问题会逼自己诚实地看一眼作品。我写的时候才发现「云端没配」这件事会影响别人复现，于是补了 `.env` 的说明。**藏起来的限制不会消失，只会在别人那里变成事故。**

（约 210 字）
